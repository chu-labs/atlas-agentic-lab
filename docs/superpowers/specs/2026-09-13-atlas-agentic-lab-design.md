# ATLAS Agentic SDLC Demo Lab — design record

Date: 2026-09-13. Lecture: Thursday 17 September 2026. Destroy by 2026-09-30.

The brief in `_scratch/atlas-agentic-sdlc-lab.md` (kept outside the repos) is the specification. This
document records only the decisions that refine or deviate from it, so a reader of the brief can see
exactly what was chosen and why.

## Decisions confirmed with the owner on 2026-09-13

| Topic | Decision | Why |
|---|---|---|
| Source project | `atlas-platform` is a **fresh build**. It borrows domain concepts from `~/Dev/chu-atlas` (five-pillar 0–100 building risk score, AU financial-year and renewal-window date math, strata policy and building shape, FastAPI + raw psycopg idiom) but copies no code, docs, hostnames or names. | chu-atlas is a read-only warehouse BFF with no tests, no rating engine, and CHU hostnames, staff names and StrataTech references throughout. Forking and scrubbing is slower and riskier than rebuilding. |
| Data richness | The platform must be data-rich enough to drive AI building reports, risk analysis, claims history and underwriting advice. | Owner requirement. |
| Data provenance | **Assumed synthetic**, generated by the seeder to match the real data's statistical shape (state mix, sum-insured and premium distributions, peril mix, claims frequency and severity, loss ratios). The owner said copying real rows is acceptable from a PII standpoint; the brief says the opposite. The seeder is built synthetic first. If the owner reaffirms copying real rows, that decision is recorded in the runbook and the seeder gains an import path. | Repos are public and the lab is internet-facing over HTTP with a shared password. |
| GitHub identity for agents | One **GitHub App** `atlas-agents` installed on `chu-labs`. Permissions: contents RW, pull requests RW, issues RW, actions RW, checks R, metadata R, workflows RW. All agents push and open PRs as `atlas-agents[bot]`. | Branch protection ignores the PR author's own approval, so agents cannot act as the owner's account. |
| Forge model | Claude Code headless with `claude-sonnet-5`. Scout, Sentinel, Conductor and Watchtower use `claude-sonnet-5` through the Anthropic API directly. | Rehearsal cost. |
| Domain / TLS | No domain. Plain HTTP on the ALB DNS name, **port-based routing**: `:80` Mission Control, `:8081` atlas-board, `:8082` atlas-platform. | No Route53 zone offered; ACM needs a domain. |
| Budget | AUD 200 ceiling is treated as AWS only. Anthropic spend is tracked per ticket and reported separately on the dashboard. | Owner did not specify; conservative reading. |

## Decisions made by the builder (presented, not objected to)

| Topic | Decision | Why |
|---|---|---|
| Database | One RDS Postgres 16 `db.t4g.micro`, `skip_final_snapshot`, three databases: `atlas`, `board`, `mission`. | About a third the cost of Aurora Serverless v2 at 0.5 ACU. |
| Egress | **No NAT gateway.** Fargate tasks run in public subnets with public IPs; security groups accept inbound only from the ALB SG. Agents need real egress to Anthropic and GitHub, which VPC endpoints cannot provide. | Saves roughly AUD 30 over the lab's life. |
| Basic auth | Middleware in each app, credential read from Secrets Manager. Agents inside the VPC call services through the ALB with the same credential. | ALB has no native basic auth. |
| Event bus | Every component emits to one EventBridge bus `atlas-lab`. Rules route: `board.issue.*` → work queue when a ticket is assigned to Forge; `*` → Mission Control SQS queue. | One bus, one contract, replayable. |
| Live feed | Mission Control backend (FastAPI on Fargate) consumes its SQS queue, persists events to Postgres, and fans out over a WebSocket through the ALB. No API Gateway, no Lambda. | Fewer moving parts; persistence is what makes `labctl record` possible. |
| Human gate | `production` GitHub environment has a required reviewer (the owner) **and** branch protection requires one approval. One dashboard **Approve** click: PR review approve → merge → approve the pending environment deployment. Both gates resolve from one human action, so there is a single pause. | Acceptance criteria: the human gate is the only pause. |
| Sentinel authority | Posts `COMMENT` or `REQUEST_CHANGES` reviews only, never `APPROVE`. | So branch protection is genuinely unsatisfiable without the human. |
| Agent authority | Encoded as YAML per agent in `agents/<name>/agent.yaml`, loaded at start, enforced by a policy check before any side effect, and shown on the fleet card. | Brief: authority as data. |
| Forge runtime | Long-running Fargate poller; on a message it runs `claude -p` as a subprocess in the same container against a fresh clone. | Matches "long-running, polling its queue" while keeping Claude Code headless. |
| Workbench | Python MCP server (stdio) `atlas-team` exposing `spawn_teammate`, `teammate_status`, `collect_teammates`. Each spawn creates a git worktree and a tmux pane running headless Claude Code. `labctl workbench` builds the layout. | Preference 1 in the brief. |
| Repo locations | Both repos are siblings under `~/Dev/mm-lecture-maq-uni-q4-26/`, pushed to `chu-labs`. | Keeps the lecture material together. |
| Secrets | Anthropic key, GitHub App private key, basic-auth credential and DB password live only in Secrets Manager. Terraform creates the secrets with placeholder values and `ignore_changes` on the value; real values are written by the CLI. | Keeps plaintext out of state. |
| VPC CIDR | `10.42.0.0/16`, two public subnets in `ap-southeast-2a/b`. | Existing account VPC uses `10.20.160.0/20`; no peering, but avoid overlap anyway. |
